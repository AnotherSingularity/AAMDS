# Threat Model

Scope: the Aeon information layer as delivered in this repository. Sponsor
environments (identity provider, cryptographic KMS/HSM, network overlay)
add their own threat model on top; this document covers what Aeon does
about the threats it can address at software level.

STRIDE tag notation: S=spoofing, T=tampering, R=repudiation, I=info-disclosure,
D=denial-of-service, E=elevation-of-privilege.

| # | Threat | STRIDE | Mitigation in Aeon |
|---|---|---|---|
| 1 | Malicious sensor input | T,D | Adapter SDK returns typed errors on malformed / oversized / clock-rollback / duplicate-sequence input. Rejected observations are persisted with reason. |
| 2 | Compromised adapter | S,T,E | Adapter capability declaration is compared against runtime expectation; adapter integrity flag propagates through normalization as `Integrity::Derived{ min_upstream }`. Adapters run in an isolated process boundary in production deployments. |
| 3 | Spoofed source | S | Integrity state must be `Verified` for a source's contributions to be trusted; unverified sources still produce tracks but the track integrity is `Derived{ min_upstream: SourceUnknown }`. |
| 4 | Replay attack | S,T | `secure-relay::signing::AntiReplayCache` rejects repeated nonces within a policy TTL. Inbound replay is out-of-scope for the baseline; adapter-side counter/nonce is a sponsor concern. |
| 5 | Message tampering | T | Envelope canonical digest binds message id, destination, kind, payload digest, timestamps, sender, nonce. Signature verification is constant-time. |
| 6 | Credential theft | S,E | Baseline: private key material is passed opaquely to the gateway. Sponsor deployments must integrate KMS/HSM through the abstraction — no default credentials, no persisted secrets in configuration. |
| 7 | Unauthorized configuration change | T,E | Config validates before activation; digest is recorded; historical config versions are preserved. Activation is out-of-band and audited. |
| 8 | Model replacement | S,T | Model artifacts carry a SHA-256 artifact digest and a signature. Only `Active` models produce corrections. Lifecycle transitions are enforced. |
| 9 | Dependency compromise | T | `tools/verify.sh security` runs `cargo audit`; SBOM (CycloneDX) generated by `verify.sh sbom`. |
| 10 | Operator privilege abuse | R,E | Every write operation on the operator API records an actor and produces an audit event. |
| 11 | Relay exfiltration | I,E | Outbound is restricted to four informational message kinds by compile-time allowlist AND runtime prohibited-content scan. Per-destination policy narrows further by classification, releasability, and payload size. |
| 12 | Denial of service | D | Bounded queues (`max_ingest_queue`, `max_relay_queue`), rate limits, dead-lettering. |
| 13 | Clock manipulation | S,T | `TimeQuality::Drifting` propagates. Rolled-back timestamps are rejected at the adapter. Latency guard rejects observations older than policy. |
| 14 | Storage corruption | T,R | Every event carries a chained SHA-256 digest. `EventStore::verify_integrity` detects tampering (unit-tested). |
| 15 | Audit deletion attempt | R | Deleting or rewriting a past event breaks the chain and fails the integrity check. |
| 16 | Rollback to vulnerable release | T,E | Release manifests are signed; ML rollback is limited to `Deprecated -> Approved -> Active`; `Revoked` is terminal. |
| 17 | Cross-tenant leakage | I | Per-destination `communities` policy: an envelope must intersect the destination's community set. |

## Explicit non-coverage

- Physical-layer attacks (RF spoofing on sensors) — sensor domain, not
  Aeon's information layer.
- Kernel exploits on the host — OS / hypervisor domain.
- Insider collusion between operator and adapter maintainer — audit is
  a detective control, not preventive; sponsor process required.
- Vendor supply-chain compromise of pinned dependencies — mitigated by
  `cargo audit` + SBOM review; residual risk requires sponsor process.
